Como funciona

        
Pediu. Recebeu um Pix.
Pagou. Recebeu.

      

      
Segue o padrão aberto x402, com o Pix como meio de pagamento: scheme exact, rede pix:br. Cada 402 gera uma cobrança Pix nova.

    


    

      
01
GET /relatorio
Pede
O cliente, pessoa ou agente, chama um recurso pago.

      
02
402 · BR Code
Recebe um Pix
O servidor responde com uma cobrança nova: valor, validade e copia e cola.

      
03
pix pago ✓
Paga
O PSP do vendedor confirma por webhook, e o pagamento é reconfirmado.

      
04
200 · recibo
Recebe
A chamada é repetida com a credencial e o recurso chega com recibo.

    


    

      

        
Para quem vende

        
Um plugin e um preço por rota. Sem cadastro, planos ou chaves.


new Elysia()
  .use(x402Pix({ facilitatorUrl, payTo }))
  .get("/relatorio", gerarPdf, {
    x402: { amount: 500 } // R$ 5,00
  })

      

      

        
Para quem compra

        
Um fetch que entende 402, respeita um teto de gasto e paga em reais.


const pagoFetch = wrapPixFetch(fetch, {
  payer: terminalPayer()
})
await pagoFetch("…/relatorio") // 402 → Pix → 200

A conta

        
Um Pix por chamada não fecha. Crédito pré-pago fecha.

      

      
Receber um Pix custa uma tarifa fixa, e um dado brasileiro custa centavos. A saída é um Pix maior que vira saldo para centenas de chamadas.

    


    

      

        
Chamada de R$ 0,051 Pix por chamada
∅

        
Chamada de R$ 1,001 Pix por chamada
80%

        
Chamada de R$ 10,001 Pix por chamada
8%

        
Depósito de R$ 20400 chamadas de R$ 0,05
4%

      

      
Tarifa do Pix sobre o valor. Referência: R$ 0,80 por Pix recebido, com mínimo de R$ 1,00 (AbacatePay). ∅ = abaixo do mínimo. O MVP cobre o Pix por chamada; o crédito pré-pago é a próxima etapa.

    

  







  

    

      

        
Segurança

        
O mesmo Pix nunca paga duas vezes.

      

      
Antes de liberar qualquer recurso, o facilitador confere tudo direto no PSP. O webhook sozinho não basta.

    

    

      
01
Cobrança de origem
Só vale a cobrança que o próprio facilitador criou.

      
02
Valor amarrado ao recurso
Um pagamento barato não libera um recurso caro.

      
03
Reconfirmação no PSP
O pagamento é checado direto no PSP antes do settle.

      
04
Sem replay
O pagamento é consumido de forma atômica, uma única vez.

      
05
Disputa e reembolso
Pix em MED ou reembolsado é recusado.

      
06
Sem dado pessoal
O CPF do pagador não chega ao servidor.

    

    
O dinheiro nunca passa por nós.
Ele cai direto na conta do vendedor.
