O HTTP 402 finalmente tem um significado. É Pix.

Agentes de IA pagam APIs brasileiras em reais, sem cadastro nem chave de API. Você faz um Pix, ele vira saldo, e a cada chamada paga a API responde 402 com o preço: o agente paga e recebe o recurso.

Cobrar por uso já é normal no Brasil. O que trava um agente de IA é tudo o que vem antes da primeira chamada: conta, contrato, chave de API e recarga num painel.


    

      

        
        
Cadastro em cada API

        
Conta, termos e chave por fornecedor. Um agente não faz isso sozinho.

      

      

        
        
Recarga manual

        
O saldo é recarregado por um humano, num painel, fornecedor por fornecedor.

      

      

        
        
Ou paga em cripto

        
As APIs brasileiras que já aceitam agentes cobram em stablecoin, não em reais.

      

    


    
O padrão mundial para agentes pagarem já existe: o x402, hoje na Linux Foundation, com Google, Visa e Mastercard. Só que em cripto. E o Pix?

Pediu. Recebeu um Pix.
Pagou. Recebeu.

      

      
Segue o padrão aberto x402, com o Pix como meio de pagamento: scheme exact, rede pix:br. Cada 402 gera uma cobrança Pix nova.

    


    

      
01
GET /relatorio
Pede
O cliente, pessoa ou agente, chama um recurso pago.

      
02
402 · BR Code
Recebe um Pix
O servidor responde com uma cobrança nova: valor, validade e copia e cola.

      
03
pix pago ✓
Paga
O PSP do vendedor confirma por webhook, e o pagamento é reconfirmado.

      
04
200 · recibo
Recebe
A chamada é repetida com a credencial e o recurso chega com recibo.

    


    

      

        
Para quem vende

        
Um middleware e um preço por rota. Sem cadastro, planos ou chaves.


const pix = pixPaywall({ facilitator, token })

app.get("/relatorio",
  pix({ amount: 500 }), // R$ 5,00
  (c) => c.json(gerar()))

      

      

        
Para quem compra

        
Um fetch que entende 402, respeita um teto de gasto e paga em reais.


const fetchPago = wrapFetch(fetch, {
  payer: terminalPayer(),
  policy: { maxPerRequest: 1000 } // teto R$ 10
})
await fetchPago("…/relatorio") // 402 → Pix → 200

Um Pix por chamada não fecha. Crédito pré-pago fecha.

      

      
Receber um Pix custa uma tarifa fixa, e um dado brasileiro custa centavos. A saída é um Pix maior que vira saldo para centenas de chamadas.

Tarifa do Pix sobre o valor. Referência: R$ 0,80 por Pix recebido, com mínimo de R$ 1,00 (AbacatePay). ∅ = abaixo do mínimo. O MVP cobre o Pix por chamada; o crédito pré-pago é a próxima etapa.

    

  







  

    

      

        
O mesmo Pix nunca paga duas vezes.

      

      
Antes de liberar qualquer recurso, o facilitador confere tudo direto no PSP. O webhook sozinho não basta.

    

    

      
Cobrança de origem
Só vale a cobrança que o próprio facilitador criou.

      
Valor amarrado ao recurso
Um pagamento barato não libera um recurso caro.

      
Reconfirmação no PSP
O pagamento é checado direto no PSP antes do settle.

      
Sem replay
O pagamento é consumido de forma atômica, uma única vez.

      
Disputa e reembolso
Pix em MED ou reembolsado é recusado.

      
Sem dado pessoal
O CPF do pagador não chega ao servidor.

    

    
O dinheiro nunca passa por nós.Ele cai direto na conta do vendedor.
